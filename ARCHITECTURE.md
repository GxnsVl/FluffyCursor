# Rendering decision

The plugin uses only common IntelliJ Platform APIs. EditorCustomElementRenderer/inlays occupy text layout space; they are unsuitable for a moving caret. Range highlighters paint document ranges, not arbitrary animated positions. Editor exposes coordinate conversion and listeners but no general caret replacement renderer. A public IdeGlassPane painter anchored to each editor content component provides an overlay without changing document layout or editor internals.

For editors implementing the public EditorEx interface, setCaretEnabled(false) temporarily disables native caret rendering while the custom painter is active. It does not disable the CaretModel, typing or navigation. The API returns the previous enabled state, which is restored on focus loss, hiding, plugin disable or disposal. The Hide native caret setting is enabled by default. Unsupported editors and windows without IdeGlassPane retain their native caret. There is no reflection, EditorImpl dependency, theme mutation, installation-file modification or input interception. Each editor owns an independent disposable controller, painter and Swing timer. Multi-carets use independent physics states and a shared timer per editor.

Positions are obtained from visualPositionToXY and lineHeight. Painting is clipped to the editor viewport. Only the union of old/new caret, trail and effect bounds is invalidated on the glass pane. Event listeners handle movement, document changes, scrolling, focus, hierarchy and theme changes. Motion stops at settlement; a separate slow blink timer only runs when blinking is requested. Hidden or unfocused editors stop timers. Document changes are coalesced onto EDT so target coordinates reflect the updated layout.

Animation uses exact elapsed-time damped-spring evolution or exponential interpolation, sampled by a 5 ms Swing timer. Parameters retain their nominal 60 Hz time units, but positions update on every tick, without frame quantization. Elapsed time is capped after event-thread stalls and animation has a maximum duration. Top and bottom edges use slightly different spring stiffness for elastic deformation. Long jumps snap; scrolling can snap and clear trails. Trails have bounded storage, distance spacing and age expiry. All optional effects are finite-duration and disabled in default presets.

Compatibility is declared for platform 243–262 (2024.3–2026.2). This is an intended verification range, not a claim that every product was manually tested. The baseline dependency is IDEA 2024.3.6; localIdePath can target an installed IDE for offline/API checks. Plugin Verifier accepted release 1.1.1 on IDEA and PyCharm 2026.2.3 and Rider 2026.2.3.1. Remote development and embedded editors require explicit verification. API inspection was performed against installed IDEA 2026.1.4 using javap.

Sources: https://plugins.jetbrains.com/docs/intellij/tools-intellij-platform-gradle-plugin.html and IntelliJ Platform Editor, IdeGlassPane, Painter API signatures.

Motion geometry writes six analytic swept-rectangle vertices into the renderer-owned Path2D, replacing per-frame point lists, sorting, hull lists and transform allocation. Glow strokes are cached. The plugin ID and settings storage names remain stable for upgrade compatibility.

## VS Code edition

The separate `vscode/` extension packages a desktop workbench renderer rather than JVM code. The public VS Code API has no arbitrary caret replacement surface. An explicit command inserts a marked local script tag into the current workbench HTML, saves its original content and checksum, and places the bundled script beside it. No installation changes occur on activation. Removal restores the backup if unchanged, or strips only the marked section if other customizations occurred later. Integrity checks and existing third-party content are preserved.

The renderer discovers focused Monaco text editors and observes native cursor layout without accessing document text. A clipped, pointer-transparent SVG draws one swept polygon and a glow per cursor. Native cursors are hidden only after valid replacement geometry is drawn. Mutation, focus, and layout events wake a requestAnimationFrame loop; it stops at settlement. Exact elapsed-time spring evolution and the same directional landing recoil are ported from the JetBrains implementation. Typing has a 70 ms movement cap and quarter-strength deformation. Scrolls and editor changes snap. Settings are serialized into the local script by the explicit install/update command; there is no IPC bridge or remote code dependency.

This renderer depends on internal Monaco DOM classes and is an unsupported VS Code customization. Browser/DOM regression checks and extension-host activation checks complement, but do not replace, manual desktop visual checks. See the VS Code guide for permissions, update handling, and recovery.

## Google Colab browser edition

`colab/build.js` copies the shared physics and adapts the renderer into a callable initializer for an isolated Manifest V3 content-script world. The scripts match only `https://colab.research.google.com/*`; only `storage` permission is requested. No service worker, broad host permission, runtime evaluation, remote script, or notebook-text collection is used. A local popup controls appearance and motion; `chrome.storage.local` changes immediately restart the overlay with the new options on open Colab pages.

The current Colab code-cell editor was inspected on the public introductory notebook: lazy editor activation creates a main-document Monaco editor, textarea.inputarea, overflow-guard viewport, and cursors-layer cursor nodes. The browser adapter also snaps on ancestor notebook-container scrolling, which moves the entire cell on the page. Cell switches restore the old native caret and initialize the new active editor. Only active local native editor cursors are targeted; output widgets and collaborator indicators are untouched. Installation-file patching from the desktop VS Code edition is not included in the browser package.

The browser package was loaded unpacked in an isolated Edge profile and tested against an intercepted local fixture using a Colab-origin URL. This validates manifest matching and storage-to-content-script updates as well as geometry and restoration; it does not constitute a full live Colab notebook editing test.
